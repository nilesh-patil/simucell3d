API reference#

SimuCell3D is used mainly as the command-line program simucell3d, configured by a parameter file and by the compile-time macros in include/global_configuration.hpp. This reference is for readers who extend the solver in C++ (a new cell class, contact model or output array) or who drive it from Python. Running simulations does not require it; see the User guide.

The C++ API is the set of headers in include/. All classes are in the global namespace, with two exceptions: the thread-placement types and functions in the namespace cpu_topology and the eigensolver in the namespace gte. Class names are lower case with underscores (solver, cell, local_mesh_refiner), and data members end with an underscore.

One iteration, class by class#

The solver runs the simulation. Each call of solver::run_iteration() passes the list of cells through the modules below, in this order. The step-by-step description, with the timers and the conditions of each step, is in Main loop.

Solver and configuration, Cell meshes

Before the first iteration, simulation_initializer reads the parameter file (parameter_reader) and the input mesh (mesh_reader), re-triangulates each cell surface (initial_triangulation) unless perform_initial_triangulation is off, and creates one object per cell.

Each page starts with the role of its classes in the simulation, a table of the classes, and a link to the user-guide chapter that explains the model. The class entries below list the public members with the comments from the headers; protected members are not listed (see the header when deriving a class). Members that exist only for some values of the compile-time macros (for example only with CONTACT_MODEL_INDEX 1 or 2) are listed whatever the configuration; their comment states the condition.
