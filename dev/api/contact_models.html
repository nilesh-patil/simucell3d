Contact models#

At each iteration, after mesh refinement, the contact model finds pairs of cells whose surfaces are within the contact cutoffs and applies adhesion and repulsion. The class is chosen at compile time by CONTACT_MODEL_INDEX in global_configuration.hpp: 0 contact_node_face_via_spring, 1 contact_node_node_via_coupling, 2 contact_face_face_via_coupling (default). All three derive from contact_model_abstract.

With contact model 2, the contact_detection_algorithm parameter selects how candidate node-face pairs are found: uspg (default) bins the bounding boxes of all faces in a uniform grid built by the model itself; sweep_and_prune uses contact_detection_sap_strategy; adaptive uses the grid and switches to sweep and prune when the number of cells reaches ADAPTIVE_SAP_CELL_THRESHOLD (500). Contact models 0 and 1 ignore the parameter and always use the uniform spatial partitioning grid of contact_model_abstract. contact_detection_uspg_strategy implements the same strategy interface on a USPG but is not queried by the contact models during a simulation. The narrative description is in Contact between cells.

Contact models#

class contact_model_abstract#

Base class of the contact models.

A contact model finds the nodes of a cell that lie within the contact cutoffs of a face of another cell and applies adhesion and repulsion to them. The solver owns exactly one model, selected at compile time by CONTACT_MODEL_INDEX in global_configuration.hpp: 0 contact_node_face_via_spring, 1 contact_node_node_via_coupling, 2 contact_face_face_via_coupling (default).

The base class holds the padded axis-aligned bounding boxes (AABB) of all faces, a uniform spatial partitioning grid of faces (USPG), and the contact detection strategy chosen by the contact_detection_algorithm parameter. With adaptive, the detection starts with the USPG and switches to sweep and prune when the number of cells reaches ADAPTIVE_SAP_CELL_THRESHOLD (500). Only contact_face_face_via_coupling consults the detection strategy; models 0 and 1 always use the USPG.

Subclassed by contact_face_face_via_coupling, contact_node_face_via_spring, contact_node_node_via_coupling

class contact_face_face_via_coupling : public contact_model_abstract#

Contact model 2 (CONTACT_MODEL_INDEX 2, default): face-face coupling.

For each node of a cell, candidate faces of other cells are those whose padded AABB contains the node. Between two epithelial cells (cell class 0), the node is coupled to the closest node of the candidate face if their distance is below the adhesion cutoff, the angle between the two node normals is at least 90 degrees, the curvature of both nodes is below surface_coupling_max_curvature, and neither node already has a closer partner on that cell. A node keeps at most one partner per adjacent cell. After the search, every group of coupled nodes is moved to its mean position. In all other cases (other cell classes, or no coupling), a node that has penetrated the face receives a repulsion force of magnitude repulsion_strength x face area x distance, shared with the face nodes by barycentric weights. Nodes whose curvature is at or above surface_coupling_max_curvature are skipped.

Candidate faces come from an internal grid binned by face AABB, or from the sweep-and-prune strategy when contact_detection_algorithm selects it.

Note

Thread-safe: contact forces are added with atomic updates and the coupling maps of the nodes are written under the node locks (node::couple_if_closest()).

void resolve_contact(const cell_ptr &c1, const cell_ptr &c2, node &n, face *f) const noexcept#

Resolve the contact between one node and one face of another cell.

Between two epithelial cells, first try to couple the node to the closest node of the face; if no coupling is stored, apply repulsion when the node lies on the inner side of the face (the side is inverted for an epithelial node against an ECM face and for a nucleus node against an epithelial face) and within the larger contact cutoff.

Parameters:

  • c1 – Cell that owns the node.

  • c2 – Cell that owns the face.

  • n – Node of c1.

  • f – Face of c2.

class contact_node_node_via_coupling : public contact_model_abstract#

Contact model 1 (CONTACT_MODEL_INDEX 1): node-node coupling.

Like contact_face_face_via_coupling, but each node has at most one partner in total (not one per adjacent cell), the angle between the normals of the two nodes must be at least 45 degrees (90 degrees in model 2), and after the search each coupled pair is moved to its midpoint. Faces are found with the uniform spatial partitioning grid of the base class; the contact_detection_algorithm parameter has no effect. Non-coupled contacts receive the same repulsion as in model 2.

Note

Repulsion forces are added without atomic operations while several threads may update the same node; the coupling itself is stored under the node lock.

class contact_node_face_via_spring : public contact_model_abstract#

Contact model 0 (CONTACT_MODEL_INDEX 0): node-face springs.

The padded AABBs of all faces are stored in the uniform spatial partitioning grid of the base class. For every node, each face of another cell whose AABB contains the node is tested: the distance d between the node and the closest point of the face decides the force, which acts along the line between the two points and is shared with the face nodes by barycentric weights. With A the face area, c the adhesion cutoff, omega the adherence_strength and xi the repulsion_strength of the face type (N/m^3):

  • node on the outer side of the face and d < c: adhesion of magnitude omega A d for d < c/2, and omega A (c - d) for d >= c/2;

  • node on the inner side and d below the repulsion cutoff: repulsion of magnitude xi A d.

The side is inverted for an epithelial node against an ECM face and for a nucleus node against an epithelial face. With POLARIZATION_MODE_INDEX 1, each face in contact is reported to its cell for polarization. The contact_detection_algorithm parameter has no effect on this model.

Note

Forces are added without atomic operations while several threads may update the same node.

Contact detection#

class contact_detection_strategy#

Interface of the broad-phase contact detection strategies.

A strategy returns, for a query position, the faces of other cells that may be in contact with it; the contact model then performs the exact distance test. The strategy is selected at run time by the contact_detection_algorithm parameter:

  • contact_detection_uspg_strategy (uspg): uniform spatial partitioning grid (USPG) of face AABBs; a query visits the voxel of the point and its 26 neighbours.

  • contact_detection_sap_strategy (sweep_and_prune): sweep and prune over the AABBs of the cells; a query visits the faces of the cells whose AABB overlaps that of the query cell.

prepare() is called once per iteration, serially, before the parallel contact loop; it may throw unstable_simulation_exception when the domain has diverged. get_candidate_faces() is called once per node inside the parallel loop and does not throw.

Usage: 

auto strategy = contact_detection_strategy::create(algorithm, params);
strategy->prepare(cells, faces, aabbs, bounds);
// for each node n of cell c:
std::vector<face*> candidates = strategy->get_candidate_faces(n.pos(), c);

Subclassed by contact_detection_sap_strategy, contact_detection_uspg_strategy

class contact_detection_uspg_strategy : public contact_detection_strategy#

Contact detection strategy based on a uniform spatial partitioning grid (USPG).

Space is divided into cubic voxels of edge 3 x min_edge_len_ + 2 x padding, where the padding is the larger contact cutoff. Each face is inserted, in Morton (Z-order) order of its AABB centre, into every voxel its padded AABB overlaps. A query returns the faces stored in the voxel of the point and its 26 neighbours, excluding faces of the query cell.

Note

contact_face_face_via_coupling bins faces in its own grid when this algorithm is selected; this class is the strategy-interface implementation of the same idea.

class contact_detection_sap_strategy : public contact_detection_strategy#

Sweep-and-prune (SAP) contact detection strategy.

Broad phase on cell bounding boxes along the three axes:

  1. Build cell-to-faces map (which faces belong to which cell)

  2. Compute cell AABBs (union of all face AABBs for each cell, with padding)

  3. Build sorted endpoint lists for X, Y, Z axes

  4. Sweep X-axis to find pairs overlapping on X

  5. Filter by Y-axis overlap

  6. Filter by Z-axis overlap

  7. Store the overlapping cell pairs, used by the queries

Complexity:

  • prepare(): O(C log C + F + P) for C cells, F faces and P overlapping cell pairs

  • get_candidate_faces(): linear in the number of faces of the cells that overlap the query cell

The result is conservative: every face that can be within the contact cutoffs of the query point is returned, possibly with extra faces.

Note

prepare() must be called from a single thread; get_candidate_faces() may then be called concurrently.
