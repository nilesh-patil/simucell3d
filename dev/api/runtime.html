Runtime support#

Thread placement, performance measurement and small utilities. The cpu_topology namespace detects the physical cores available to the process and pins one OpenMP thread per physical core unless SIMUCELL3D_PIN_THREADS=0 or OMP_PLACES is set (Parallel performance). PerformanceMonitor times the phases of each iteration and feeds the diagnostics CSV. utils.hpp holds helper templates for number formatting and floating-point comparison.

Thread placement#

namespace cpu_topology#

Detection of logical CPUs and physical cores, and thread pinning.

Header-only. Topology information is read from Linux sysfs; on other systems every logical CPU is treated as its own core and pinning is not available.

Functions

inline std::vector<int> parse_cpu_list(const std::string &text)#

Parse a kernel CPU list such as “0,4”, “0-3” or “0-1,4-5”.

Parameters:

text – CPU list in the kernel’s list format.

Returns:

Sorted, unique CPU ids. Malformed tokens are ignored.

inline std::vector<int> placement_order(const topology &topo)#

Order in which OpenMP threads are assigned to logical CPUs.

The lowest-numbered CPU of every physical core comes first, so that up to topology::nb_physical_cores() threads never share a core; the remaining hyperthread siblings follow. Cores are taken round-robin across packages, so consecutive threads on a multi-socket host are spread over the sockets’ memory controllers.

Parameters:

topo – Topology returned by detect().

Returns:

Logical CPU ids; thread i is pinned to element i.

  • fallback – Value returned when the file cannot be read.

Returns:

The integer in the file, or fallback.

inline topology detect(const std::vector<int> &allowed_cpus)#

Group logical CPUs into packages and cores using sysfs.

Without sysfs (non-Linux systems, containers with a masked /sys) every CPU is treated as its own core in package 0.

Parameters:

allowed_cpus – Logical CPU ids, usually allowed_cpus().

Returns:

The topology of those CPUs.

inline std::vector<int> query_allowed_cpus()#

Query the logical CPUs this process may run on.

If libgomp built a place list (OMP_PROC_BIND or OMP_PLACES set in the environment), the main thread is already pinned to a single CPU when main() runs and sched_getaffinity() would under-report; the place list is then the only record of the original taskset or cgroup mask, and it is used first. Otherwise the affinity mask is used, and as a last resort all omp_get_num_procs() CPUs.

See also

allowed_cpus(), which caches the result.

Returns:

Sorted logical CPU ids.

inline const std::vector<int> &allowed_cpus()#

The logical CPUs this process may run on, captured once on first use.

The value is cached because, after the first solver has pinned the calling thread, sched_getaffinity() reports a single CPU, and every later solver built in the same process (tests, Python bindings, benchmark drivers) would otherwise use one thread.

Returns:

Reference to the cached result of query_allowed_cpus().

inline bool pinning_requested()#

Whether the solver should pin its OpenMP threads.

Pinning is on by default. It is disabled by SIMUCELL3D_PIN_THREADS=0, and by any OMP_PLACES setting, which is taken as a placement chosen by the user.

Returns:

true if threads should be pinned.

inline bool pin_current_thread(int cpu_id)#

Restrict the calling thread to one logical CPU.

Parameters:

cpu_id – Logical CPU id.

Returns:

false if the operating system refused, or on non-Linux systems.

inline int current_thread_cpu()#

The single CPU the calling thread is restricted to.

Returns:

The logical CPU id, or -1 if the thread may run on several CPUs or the query is not supported.

Performance monitoring#

class PerformanceMonitor#

Accumulates wall-clock times of named phases.

The solver times four phases of each iteration with ScopedTimer: “mesh_refinement”, “contact_detection”, “polarization_and_internal_forces” and “time_integration”. It reads the statistics with get_stats() when it writes the diagnostics CSV (every 100 iterations) and then calls reset(), so each row covers one 100-iteration window. With verbose output, report() is printed at the end of the run.

Usage: 

PerformanceMonitor monitor;
{
    PerformanceMonitor::ScopedTimer timer(monitor, "contact_detection");
    contact_model->run(cells);
}
monitor.report();

Note

record() and the timers are not thread-safe: use them outside parallel regions. record_thread_balance() is the only member meant to be called inside one.

inline void record_thread_balance(const std::string &name, std::chrono::high_resolution_clock::time_point start_time)#

Record the time one thread spent in a parallel region.

Call inside the parallel region, once per thread: 

#pragma omp parallel
{
    auto start = std::chrono::high_resolution_clock::now();
    #pragma omp for schedule(runtime)
    for (int i = 0; i < n; i++) { work(i); }
    monitor.record_thread_balance("my_loop", start);
}

Note

Thread-safe (the update is in an OpenMP critical section). The solver does not call it; the samples are not cleared by reset().

Parameters:

  • name – Region name.

  • start_time – Time at which the thread entered the region.

inline void analyze_thread_balance() const#

Print the load-balance statistics of every region recorded with record_thread_balance(), with a warning above 20 % imbalance.

inline void export_to_csv(const std::string &filename, int iteration = -1, size_t num_cells = 0) const#

Append one row per phase to a CSV file.

Columns: iteration, num_cells, phase, avg_ms, min_ms, max_ms, count, total_ms. The header is written when the file does not exist yet. If the file cannot be opened, an error is printed to standard error and nothing is written. Not used by the solver, which writes its own diagnostics CSV.

Parameters:

  • filename – Path of the CSV file.

  • iteration – Iteration number written in the first column.

  • num_cells – Cell count written in the second column.
