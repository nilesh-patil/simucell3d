Release 1.0#

Release 1.0.0 (Zenodo archive 2024-03-08; tag v1.0 2024-06-26)

The code published with Runser, Vetter & Iber (2024), “SimuCell3D: three-dimensional simulation of tissue mechanics with cell polarization”, Nature Computational Science 4, 299-309 (doi:10.1038/s43588-024-00620-9). The project was then called DCM.

Use 1.0 to reproduce or compare with the figures of the paper: later releases change simulation results (Release 2.1).

Obtaining 1.0#

Two snapshots of the 1.0 code exist, and they are not identical:

Zenodo archive

Tag v1.0

Identifier

doi:10.5281/zenodo.10796908, cited by the paper (its ref. 76)

git tag v1.0 of this repository, the head of the Iber Lab repository

Commit

5342bf8 (2024-03-07; archive published 2024-03-08)

38af451 (2024-06-26), a later commit by the same author

Default CONTACT_MODEL_INDEX

1 (node-node coupling, described in the paper)

2 (face-face coupling, not described in the paper)

Input files of Figs. 1 and 3

not included

fig_1_*.vtk, fig_3_vesicle.vtk, parameters_vesicle.xml, parameters_sheet.xml, parameters_tube.xml

The source files in src/ are the same in both. It is not documented which contact model produced each published figure; the input files added in 38af451 are written for model 2. When you compare with a published figure, record which snapshot and which CONTACT_MODEL_INDEX you used. The raw data of the paper are archived separately, doi:10.5281/zenodo.10797576.

$ git clone https://github.com/nilesh-patil/simucell3d.git
$ cd simucell3d
$ git checkout v1.0      # the tag; or: git checkout 5342bf8 for the archived commit

Building and running 1.0#

Release 1.0 has the same requirements as 2.1 except that it accepts older CMake versions; it was checked with CMake 3.18 and GCC 10. CMake 4 refuses its cmake_minimum_required(VERSION 3.0); with CMake 4, add -DCMAKE_POLICY_VERSION_MINIMUM=3.5 to the cmake line. From the repository root (the last line needs the tag, because the archive has no parameters_vesicle.xml):

$ sed -i 's|/data/input_meshes/fig_3_vesicle_triangulated.vtk|data/input_meshes/fig_3_vesicle.vtk|' parameters_vesicle.xml
$ mkdir build
$ cd build
$ cmake -DCMAKE_BUILD_TYPE=Release ..
$ make -j4
$ ./simucell3d ../parameters_vesicle.xml

The sed line is needed because parameters_vesicle.xml of the tag names the input mesh /data/input_meshes/fig_3_vesicle_triangulated.vtk, which is not in the repository; without it the run stops at once with “ERROR: input mesh file … not found”. 2.x ships the corrected path. parameters_default_dynamic.xml, which is in both snapshots, runs without an edit, but it is written for CONTACT_MODEL_INDEX 1: the default at the archived commit, not at the tag.

Differences from 2.1 that affect command lines and scripts:

  • The parameter files are in the repository root (parameters_vesicle.xml, parameters_default_dynamic.xml, …), not in parameters/core/.

  • The executable takes exactly one argument, the parameter file. The options --schedule, --threads, --output-dir, --diagnostics-csv and --version do not exist; no performance_diagnostics.csv is written.

  • The compile-time options in include/global_configuration.hpp have the same names (POLARIZATION_MODE_INDEX, CONTACT_MODEL_INDEX, DYNAMIC_MODEL_INDEX).

The 1.0 documentation is the README.md and doc/ folder of the tag. That release’s own documentation, re-rendered and not updated, is at https://www.nilesh42.science/simucell3d/1.0/.

Measured behaviour of 1.0 (November 2026)#

The November 2026 benchmark ran the tag v1.0 on 8-core cloud machines (GCP c2-standard-16, 8 threads), with the compile-time switches named in each parameter file, next to later versions (Benchmarks). For someone who wants to reproduce the paper with 1.0, it found:

  • The growth benchmark does not reach the regime of Fig. 1e. With the lab’s benchmark file of the tag, parameters_benchmarck.xml (contact model 1, polarization mode 0), 1.0 stops with “The refinement of the mesh of cell N failed. The simulation is unstable.” at 126 to 165 cells, after about \(10^{-4}\) s of simulated time, at each of four time steps from 1e-7 s to 1.25e-8 s. 1.0 with two crash fixes (the local-id resynchronisation and the face-orientation fix of 2.1) follows the same growth curve and then stops with the same error, at 25,129, 22,719 and 42,335 cells in three runs at 2.5e-8 s.

  • The single-cell test files do not start. On the one- and two-cell files of test/test_scientific_benchmarks/ in 2.x, which use only parameter tags that 1.0 reads, 1.0 stops at iteration 0 with the same error.

  • Some parameter values never complete. Of five values of the apical-to-lateral tension ratio on the Fig. 3 vesicle (without growth), 1.0 completes only one; with the two crash fixes, the lowest and highest values failed in all three attempts each. Of the 20 cases of the benchmark, 1.0 completes 6; each of the others ends with the mesh-refinement error (Which cases complete).

  • Where 1.0 runs, its results are close to those of 2.1.0, except in two cases. Most of these comparisons use 1.0 with two crash fixes, because 1.0 itself completes only one vesicle ratio.

    • At ratios 1.5 and 2, 1.0 with two crash fixes and 2.1.0 agree to within 0.5% in pressure and 0.1% in sphericity.

    • On the tube and on the multilayer vesicle, the end states of 1.0 and 2.1.0 agree to within the spread between builds.

    • At ratio 3, the mean pressure is 444-446 Pa in 1.0 with two crash fixes, against 348-355 Pa in every 2.x build. 1.0 itself stops at about iteration 48,000 there, but its pressure up to that point matches the crash-fixed build.

    • In the monolayer vesicle, the mean pressure is 20 Pa in 1.0 against 25-27 Pa in 2.x.

    • In both differing cases, 1.0 detects less contact area from the first iterations: a contact-area fraction of 0.71 against 0.76 at ratio 3, and 0.03 against 0.06 in the monolayer.

A likely cause of the two differences, not yet confirmed, is the closest-point error of 1.0. In src/contact_models/contact_model_abstract.cpp:237 (function compute_node_triangle_distance, the same in the Zenodo archive) the closest point in the interior of a triangle is computed as

const vec3 cpa = a + ab * v + a + ac * w;

with the vertex a added twice. The point is displaced by the position vector of a, so a contact in the interior of a face falls outside the cutoff and is not detected. 2.0 corrected the line (Release 2.1). This is an inference from the outputs: the deciding test, 1.0 with only that line changed and rerun on the two cases, has not been run.
