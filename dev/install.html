Installing SimuCell3D#

SimuCell3D is distributed as source code and built with CMake. The build produces one command-line program, simucell3d, and optionally a Python module that drives the same solver. There are two ways to install it:

  • Building from source: compile on Linux, or on Windows through the Windows Subsystem for Linux (WSL).

  • Docker: build a container image that contains the compiled program.

Requirements#

Requirement

Version

Notes

Operating system

Linux

On Windows, use WSL. Other platforms are not tested.

C++ compiler

C++17, with OpenMP

GCC 10 or newer.

CMake

3.10 or newer

CMake 4 is supported.

OpenMP

Required by every module (find_package(OpenMP REQUIRED)). GCC ships it as libgomp.

git

To obtain the source.

Python 3

Only for the optional Python module and the analysis scripts in scripts/.

The other C++ dependencies (tinyxml2 for the parameter file, delaunator for the triangulation of division planes, and pybind11 for the Python module) are included in the lib/ directory of the repository.

On Debian or Ubuntu the build tools are installed with:

$ sudo apt-get install build-essential cmake git

Building from source#

Clone the repository and build in Release mode in a build/ directory:

$ git clone https://github.com/nilesh-patil/simucell3d.git
$ cd simucell3d
$ mkdir build
$ cd build
$ cmake -DCMAKE_BUILD_TYPE=Release ..
$ make -j4

-j4 compiles four files in parallel; use a higher number on a machine with more cores, or a lower one if the compiler runs out of memory. A Release build is important: a Debug build of the solver is much slower.

The executable is built as build/src/app/simucell3d. After every build, CMake also creates the symbolic link build/simucell3d to it; the documentation runs the program through that link, from the build/ directory.

Note

The path of the source directory is compiled into the program (PROJECT_SOURCE_DIR). It is used to find input meshes given by a relative path such as data/input_meshes/fig_3_vesicle.vtk (Parameter file reference). If the repository is moved after the build, run cmake again.

Verifying the build#

From the build/ directory, print the version:

$ ./simucell3d --version
SimuCell3D 2.1.0 (<commit>)

The text in parentheses is the git commit the build was configured from; it is unknown when the source is not a git checkout.

The test suite is registered with CTest and is built together with the program. To run all tests, or only those whose name starts with a prefix (here the input/output tests):

$ ctest
$ ctest -R io_

The complete suite takes a while; the Testing page describes its parts.

Compile-time configuration#

The contact model, the dynamic model and the polarization mode are selected when the program is compiled, by three macros in include/global_configuration.hpp:

#define POLARIZATION_MODE_INDEX 1
#define CONTACT_MODEL_INDEX 2
#define DYNAMIC_MODEL_INDEX 0

These are the defaults, and the configuration that most shipped parameter files assume. To use another configuration, edit the header and rebuild. The meaning of each value, and which parameter file needs which configuration, is described in Compile-time configuration.

Python module (optional)#

The Python module simucell3d_python_wrapper is built when CMake is configured with -DENABLE_PYTHON_BINDINGS=TRUE:

$ cmake -DENABLE_PYTHON_BINDINGS=TRUE -DPYTHON_EXECUTABLE=$(which python3) -DCMAKE_BUILD_TYPE=Release ..
$ make -j4

The compiled module is written to build/bin/python_bindings/. Its use is described in Python interface.

Docker#

The Dockerfile in the repository root builds SimuCell3D (Release, with the Python module) in a container based on the python:3.10 image. It requires Docker.

$ git clone https://github.com/nilesh-patil/simucell3d.git
$ cd simucell3d
$ docker build -t simucell3d_docker_img .

The source tree is copied to /app in the image and built in /app/container_build, which is also the working directory of the container. The entry point is the executable /app/container_build/src/app/simucell3d, so the arguments of docker run are passed to it. Run a simulation from the repository root with:

$ mkdir -p simulation_results
$ docker run -it -v "$(pwd)/simulation_results":/app/simulation_results \
    simucell3d_docker_img:latest ../parameters/core/parameters_vesicle_quick.xml

  • The parameter file path is relative to /app/container_build. Only files that were in the repository when the image was built are available; after adding or changing a parameter file or a mesh, build the image again.

  • The shipped parameter files write to ../simulation_results/<name>, that is to /app/simulation_results/<name> in the container. The -v option mounts that directory on simulation_results/ in the current directory, so the results remain after the container exits.

  • Options such as --threads=N are appended after the parameter file, as with the native executable (Running simulations).

Troubleshooting#

CMake reports Could NOT find OpenMP_CXX

The compiler has no OpenMP support. With GCC, OpenMP is part of the compiler packages (build-essential on Debian and Ubuntu). With another compiler, install its OpenMP runtime, or select GCC with cmake -DCMAKE_CXX_COMPILER=g++ .. in an empty build directory.

The compiler is killed or the machine runs out of memory during make

Reduce the number of parallel jobs, for example make -j2.

./simucell3d: No such file or directory

The command is not run from the build/ directory, or the build failed before the link step. Check the end of the make output.

The program cannot find an input mesh

See Frequently asked questions.
