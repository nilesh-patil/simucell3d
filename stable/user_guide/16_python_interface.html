Python interface#

SimuCell3D includes an optional Python module, simucell3d_python_wrapper, built with pybind11. It runs the same solver as the simucell3d executable, but takes its parameters from Python objects instead of an XML file and returns the per-cell statistics and the final cells to Python. It is useful for scripted parameter studies and for analysing results without going through files.

The module is a thin layer over the C++ structures. Its names end in an underscore, its constructor runs the whole simulation, and it does not validate parameters. This chapter describes how to build and import it, every class and attribute it exports, and its limitations.

Building the module#

The module is not built by default. Configure with ENABLE_PYTHON_BINDINGS set to TRUE; the pybind11 sources are included in lib/pybind11, so only the Python development headers (Python.h) are needed in addition to the usual build requirements (Installing SimuCell3D). From the repository root:

$ cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DENABLE_PYTHON_BINDINGS=TRUE \
      -DPYTHON_EXECUTABLE=$(which python3)
$ cmake --build build --target simucell3d_python_wrapper -j 4

-DPYTHON_EXECUTABLE selects the interpreter the module is built for; the module can only be imported by that Python version. CMake prints -- Python bindings enabled when the option is active. Omitting --target builds the module together with everything else.

The module is written to build/bin/python_bindings/, with a name such as simucell3d_python_wrapper.cpython-310-x86_64-linux-gnu.so (the middle part depends on the Python version and platform).

The Docker image (Running simulations) builds the module, in /app/container_build/bin/python_bindings/.

Note

The continuous-integration builds do not build the Python module. For the 2.1 release it was built and run on Linux with Python 3.10 and GCC. It uses the vendored pybind11 2.11.

Importing the module#

Python finds the module once its directory is on the module search path, either through PYTHONPATH:

$ export PYTHONPATH=$PWD/build/bin/python_bindings:$PYTHONPATH
$ python3 -c "import simucell3d_python_wrapper as sc; print(dir(sc))"

or from inside a script, as scripts/python_bindings/launch_simulation_example.py does:

import sys
sys.path.insert(0, "/path/to/simucell3d/build/bin/python_bindings")
import simucell3d_python_wrapper as sc

The module exports six classes: global_simulation_parameters, cell_type_parameters, face_type_parameters, simulation_outputs, cell and simucell3d_wrapper.

A complete run#

The following script runs one epithelial cell (data/input_meshes/big_sphere.vtk) for 100 time steps and reads the results. It follows launch_simulation_example.py, with a shorter duration.

import sys
from io import StringIO

import pandas as pd

sys.path.insert(0, "build/bin/python_bindings")
import simucell3d_python_wrapper as sc

# Numerical parameters (the <numerical_parameters> section of a parameter file)
sim = sc.global_simulation_parameters()
sim.input_mesh_path_ = "data/input_meshes/big_sphere.vtk"
sim.output_folder_path_ = "python_run"  # deleted and re-created by the run
sim.damping_coefficient_ = 2e-9         # kg/s
sim.simulation_duration_ = 1e-5         # s
sim.sampling_period_ = 5e-6             # s
sim.time_step_ = 1e-7                   # s
sim.min_edge_len_ = 1e-6                # m
sim.contact_cutoff_adhesion_ = 7.5e-7   # m
sim.contact_cutoff_repulsion_ = 7.5e-7  # m
sim.enable_edge_swap_operation_ = False
sim.perform_initial_triangulation_ = False

# One face type (a <face_type> block)
apical = sc.face_type_parameters()
apical.name_ = "apical"
apical.face_type_global_id_ = 0
apical.surface_tension_ = 1e-3          # N/m
apical.bending_modulus_ = 0.0           # J
apical.adherence_strength_ = 0.0        # N/m^3
apical.repulsion_strength_ = 1e9        # N/m^3

# One cell type (a <cell_type> block)
epithelial = sc.cell_type_parameters()
epithelial.name_ = "epithelial"
epithelial.global_type_id_ = 0          # cell class: epithelial
epithelial.mass_density_ = 1e3          # kg/m^3
epithelial.bulk_modulus_ = 1e4          # Pa
epithelial.max_pressure_ = 1e20         # Pa
epithelial.initial_pressure_ = 0.0      # Pa
epithelial.area_elasticity_modulus_ = 0.0       # J
epithelial.target_isoperimetric_ratio_ = 150
epithelial.angle_regularization_factor_ = 0.0   # J
epithelial.avg_growth_rate_ = 2e-11     # m^3/s
epithelial.std_growth_rate_ = 0.0
epithelial.avg_division_vol_ = 1e-14    # m^3
epithelial.std_division_vol_ = 0.0
epithelial.min_vol_ = 3.7e-17           # m^3
epithelial.surface_coupling_max_curvature_ = 1e7  # 1/m
epithelial.add_face_type(apical)

# Run: positional arguments (parameters, cell types, verbose, number of threads)
run = sc.simucell3d_wrapper(sim, [epithelial], False, 2)
out = run.get_simulation_outputs()

if out.RETURN_CODE_:
    print("Simulation failed:", out.error_message_)
else:
    stats = pd.read_csv(StringIO(out.cell_statistics_))
    print(stats[["iteration", "cell_id", "volume", "pressure"]])
    for c in out.cell_lst_:
        print(c.get_id(), c.get_volume(), len(c.get_node_coord_lst()))

Run it from the repository root. The relative mesh path is also found from other directories, because, as in the command-line program, a mesh path that does not exist is tried again relative to the source directory the module was built from (Paths).

In this example the sphere is larger than avg_division_vol_, so the cell divides at the first division check and the run ends with two cells.

Methods:

add_face_type(face_type)

Append a face_type_parameters object to the cell type. The order of the calls is the order of the face types; for epithelial cells it must be apical, lateral, basal (Face types). The face types cannot be read back from Python.

add_additional_parameter(name, value)

Store a named number in the cell type. No part of SimuCell3D 2.1 reads these values.

simucell3d_wrapper#

simucell3d_wrapper(simulation_parameters, cell_type_list, verbose, nb_threads)

Constructing the object runs the complete simulation and returns when it has finished. The four arguments are required and positional; keyword arguments raise a TypeError (“incompatible constructor arguments”).

simulation_parameters

A global_simulation_parameters object.

cell_type_list

A list of cell_type_parameters objects. The input-mesh cell_type_id indexes this list.

verbose

bool. If True, the run prints the same progress information as the command-line program.

nb_threads

int. Number of OpenMP threads; 0 or a negative value means one thread per physical core. The scheduling mode is always adaptive.

Method:

get_simulation_outputs()

Return a simulation_outputs object with the result of the run.

An error during the run (an invalid mesh, a diverged simulation, Ctrl-C in the terminal) does not raise a Python exception. It ends the run and is reported in the outputs.

Differences from the command-line program#

  • Files. The run writes cell_data/ and face_data/ meshes and, every 100 iterations, performance_diagnostics.csv to output_folder_path_, which is deleted at the start as for the command-line program. It does not write simulation_statistics.csv; the table is returned in cell_statistics_ instead.

  • No validation. The range checks of the parameter-file reader (Numerical parameters) are not applied. A zero time step, a sampling period smaller than the time step or a negative modulus is accepted and gives meaningless results or a failed run. Use values that a parameter file would accept.

  • No contact detection choice. contact_detection_algorithm cannot be set.

  • Compile-time options. The contact model, dynamic model and polarization mode are those of the build (Compile-time configuration).

  • The interpreter is blocked. The constructor holds the Python interpreter until the run ends; other Python threads do not run in the meantime. Ctrl-C is checked once per iteration and stops the run with RETURN_CODE_ set to True.

  • Thread pinning affects the calling thread. With thread pinning on (the default), the thread that calls the constructor is pinned to one CPU and stays pinned after the run, which slows down other multi-threaded work in the same Python process (for example NumPy). Set the environment variable SIMUCELL3D_PIN_THREADS=0 before the run if that matters.

  • Memory. All statistics rows are kept in memory until the run ends.

The example script#

scripts/python_bindings/launch_simulation_example.py runs a single cell from data/input_meshes/big_sphere.vtk for \(10^{-3}\) s (\(10^4\) iterations), saves the statistics as build/python_sim_example/cell_statistics_data.csv and prints them. It expects the module in build/bin/python_bindings/ of the same checkout and needs pandas:

$ pip install pandas
$ python3 scripts/python_bindings/launch_simulation_example.py

To run many simulations, call simucell3d_wrapper in a loop, or in separate processes with multiprocessing and nb_threads set so that the processes do not share cores. Give every run its own output_folder_path_. The example page Batch runs from Python shows a batch of runs.
