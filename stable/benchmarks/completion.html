Which cases complete#

Each build ran the same 20 cases with the paper’s parameters (Method). A case completes when every run of it reached its end, or its planned time cap, without the solver removing a cell. 1.0 completes 6, 1.0 with two crash fixes 8, 2.0 13, the four intermediate builds 15 or 16, and 2.1.0 17.

The three cases 2.1.0 misses#

Growth benchmark at the published time step, 1e-7 s

2.1.0 grows the aggregate to 150,000 cells but removes cells as unstable on the way: 93,310 removals in the full run, the first at about 4,800 cells. No build completes this case. Stable time step gives the details and the step that works.

Monolayer vesicle, shipped file (fig3e_monolayer.xml, 1e-2 s)

No build survives it. 1.0 stops with the refinement error, 2.0 crashes, and every later build removes most of its cells: 2.1.0 ends with 18 of 434 cells and exit status 0 (Limits of the model). The same file run by the paper protocol (to 1.736e-4 s) completes in every build.

Two cells in contact, smaller minimum edge length

Every build that can start this file loses a cell. In 2.1.0 the cell is removed at iteration 204 for excessive extent, with no non-finite node. Whether this is the same defect as the node blow-ups at 1e-7 s is not established. The same file with the shipped edge length completes in 2.1.0.

How 1.0 fails#

All 14 cases that 1.0 does not complete end the same way, with its mesh-refinement error:

The refinement of the mesh of cell N failed

On the growth benchmark this happens at every time step, at 126 to 165 cells, after about 1e-4 s of simulated time. On the four shipped analytic files it happens at iteration 0, so 1.0 cannot start them. With the smaller minimum edge length (1.5e-7 m), 1.0 completes the two-cells-apart case and stops at iteration 38 on the two-cells-in-contact case. The two crash fixes move the growth-benchmark failure later (to 22,719 to 42,335 cells at 2.5e-8 s) but do not remove it, and the size at which a run stops is not reproducible.

2.0 no longer stops with the refinement error on the vesicle and analytic files, but it crashes on the growth benchmark: every one of its growth runs fails by 216 cells, a few iterations after its first cell removal. 2.0 lacks the resync of local cell ids after a removal, which is one of the two crash fixes and is part of 2.1.0.

The last column divides all machine hours a build spent on the sweep, failed runs included, by its number of usable runs.

The failures of 1.0 depend on the parameter, not on chance: with its crash fixes, 1.0 never completes ε = 1.0 or ε = 4.0 in three attempts each, so those values return no result at any budget. Across every paper-parameter case that runs to a fixed end, 33% of the runs of 1.0 are usable, 48% with its crash fixes, 80% in 2.0 and 92% in 2.1.0.

Usable is a low bar: it means the run finished cleanly, not that the tissue it produced is biologically right. Limits of the model shows cases where it is not.
