Use 1.0 to reproduce or compare with the figures of the article. Later releases change simulation results; the release notes of 1.0 compare the two 1.0 snapshots, and the release notes of 2.1 list what changed since 1.0, including defects of 1.0 found later.

Obtaining and building 1.0#

The tag is in the repository of the 2.x releases:

$ git clone https://github.com/nilesh-patil/simucell3d.git
$ cd simucell3d
$ git checkout v1.0      # the tag; or: git checkout 5342bf8 for the archived commit

Build from the repository root. Release 1.0 needs a C++17 compiler with OpenMP and CMake; it declares cmake_minimum_required(VERSION 3.0), which CMake 3.x accepts with a deprecation warning and CMake 4 refuses. With CMake 4, add -DCMAKE_POLICY_VERSION_MINIMUM=3.5 to the cmake line.

$ sed -i 's|/data/input_meshes/fig_3_vesicle_triangulated.vtk|data/input_meshes/fig_3_vesicle.vtk|' parameters_vesicle.xml
$ mkdir build
$ cd build
$ cmake -DCMAKE_BUILD_TYPE=Release ..
$ make -j4
$ ./simucell3d ../parameters_vesicle.xml

The executable takes one argument, the parameter file. The parameter files are in the repository root. Each one names, in a comment at its top, the compile-time settings it needs in include/global_configuration.hpp. parameters_vesicle.xml needs POLARIZATION_MODE_INDEX 1, CONTACT_MODEL_INDEX 2 and DYNAMIC_MODEL_INDEX 0, which are the defaults of the tag, so a default build runs it.

Note

The sed line is needed because parameters_vesicle.xml of the tag names the input mesh /data/input_meshes/fig_3_vesicle_triangulated.vtk, which is not in the tag; without it the run stops at once with “input mesh file … not found”. Other files need a different build: parameters_default_dynamic.xml, for example, is written for CONTACT_MODEL_INDEX 1, the default of the archived commit 5342bf8 but not of the tag. Change the setting in include/global_configuration.hpp and rebuild before you run such a file.
