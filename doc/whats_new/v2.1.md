# Release 2.1

**Release 2.1.0** (unreleased)

SimuCell3D 2.1 is a maintenance and robustness release of the code published with
Runser, Vetter & Iber (2024) ({doc}`/citing`). It fixes bugs in the 1.0 physics and mesh code,
adds safeguards that keep long growth runs alive, and makes the contact step faster. It adds no
new biological model. These notes compare 2.1 with 1.0, the version used in the paper; items
marked *(2.0)* were already part of {doc}`v2.0`. The authoritative, complete list of changes is
[`CHANGELOG.md`](https://github.com/nilesh-patil/simucell3d/blob/main/CHANGELOG.md) in the
repository.

:::{important}
**Results differ from 1.0.** A simulation run with 2.1 does not reproduce the numbers produced
by 1.0. Several 1.0 bugs changed the physics, and fixing them changes trajectories. 2.1 also
adds safeguards that delete or repair cells that 1.0 would have kept, or crashed on. To compare
with the published figures, re-run the comparison with release 1.0 ({doc}`v1.0`) rather than
mixing results from the two versions.
:::

## Changed behaviour

The following fixes change simulation results compared with 1.0.

Contact distance to a face interior *(2.0)*
: When a node projected onto the inside of a triangle, 1.0 computed the closest point with one
  triangle vertex counted twice, so the distance was measured to the wrong point and repulsion
  missed contacts in face interiors. The closest point is now computed correctly.

Semi-implicit Euler step for coupled nodes *(2.0)*
: With the full equations of motion (`DYNAMIC_MODEL_INDEX 0`) and face-face coupling, 1.0 moved
  nodes coupled across a cell-cell contact with their old momentum, which is an explicit
  (forward) Euler step. The momentum is now updated first, and the new averaged momentum moves
  the coupled nodes, as the semi-implicit scheme requires.

Coupling partner lookup ([#113](https://github.com/nilesh-patil/simucell3d/issues/113))
: The face-face coupling model looked up a node's partner by the other cell's global id in a
  table indexed by local id. After cells had divided the two ids differ, and the partner became
  whichever candidate a thread visited last. The partner is now the nearest node.

Face orientation after an edge split
: When the mesh refiner split an edge, it oriented the new triangles with normals stored on the
  old faces, which can be out of date. Some new triangles came out inside-out; the affected cell
  then mis-measured its volume, lost pressure resistance to compression and swelled or
  stretched. The new triangles now copy the orientation of the face they replace. 1.0 has the
  same bug.

Division when the cutting plane crosses the surface more than once
: If the division plane also cut a thin protrusion of the cell, 1.0 followed only one
  intersection loop, the division failed and the cell retried at every iteration. Every loop is
  now traced, the cell is cut along the longest one, and a flood fill that does not cross the cut
  separates the two daughters. When the Delaunay triangulation of the cut face does not cover its
  whole outline, the division is refused and the mother tries again at the next division check;
  the log line names the cell. See {ref}`whatsnew-v2-1-known-issues`.

Bending force on sliver triangles
: The bending force contains $1/A$ and $\cot\theta$ terms and could become more than $10^6$
  times larger than normal on a nearly flat triangle. A hinge is now skipped when one of its two
  triangles has an area below $10^{-4}$ times the square of its longest edge, and
  $|\cot\theta|$ is capped at 1000. Well-shaped triangles give the same force as before.

## Added safeguards

These mechanisms are not part of the model described in the paper. Each one is logged, so that
its frequency in a run can be checked. The user guide describes them in
{doc}`/user_guide/09_safeguards`.

- **Unstable cells are deleted.** A cell is removed if any node coordinate is not a finite
  number, or if its bounding box is wider than 10 times the cube root of its target volume. Each
  removal is logged to standard error and counted in the `unstable_cells_removed` column of the
  diagnostics CSV.
- **Inside-out and self-intersecting cells are deleted.** A cell is also removed if its signed
  volume is zero or negative, or if its volume exceeds the volume of its bounding box. The log
  line names the reason (`negative volume`, `volume exceeds bounding box`). Static cells are
  exempt.
- **The mesh refiner gives up on an oscillating cell** *(2.0; the log message is new in 2.1)*.
  When refinement keeps undoing itself at the same place, the refiner stops working on that cell
  for the current time step, logs it and lets the run continue. Some edges of that cell may stay
  outside the edge-length bounds until the next step. 1.0 aborted the run with "The refinement of
  the mesh of cell X failed."
- **Face orientation self-check.** After every mesh refinement each cell checks that its faces
  are oriented consistently; a cell that fails is logged and re-oriented. The check costs about
  0.25% of a time step.
- **The contact grid refuses a diverged domain.** If node coordinates are infinite or too large
  for the spatial grid, the run stops with an error instead of hanging.
- **A cell whose mesh refinement fails is deleted.** If refining one cell's surface throws an
  error, that cell is removed right after refinement and the run continues. Each removal is
  logged (`Removing cell <id> at iteration <n>: mesh refinement failed: <error>`) and counted in
  `unstable_cells_removed`. The run still stops on a diverged domain, when out of memory, and when
  more than max(10, 1% of the cells) fail in one iteration, or all of them do.

## Fixed

- Crash after a cell was removed: the remaining cells kept stale local ids, which the contact
  model uses as list indices (segmentation fault at about 2,700 cells in the paper
  configuration).
- Race condition in cell division: daughters were appended to the cell list from inside the
  parallel loop that iterates over it.
- Heap use-after-free in the edge split of the mesh refiner. *(2.0)*
- Division-by-zero guards in matrix inversion and vector angle calculations. *(2.0)*
- Integer overflow in the spatial grid (USPG): in voxel indexing *(2.0)*, and in the voxel count
  of a very large domain, which caused a 20-hour stall.
- The membrane elasticity energy in the output was always 0.
- The growth phase in the diagnostics could never be detected.
- Face-face coupling under contention: threads read a node's coupling map while others wrote to
  it, and a farther partner could overwrite a closer one. The closest-partner rule is now applied
  under both nodes' locks.
- Contact forces added to the nodes of neighbouring cells were lost under contention; they now
  use an atomic add. ThreadSanitizer reported 43 races in contact resolution before this fix and
  none after.
- An error raised during contact detection now reaches the error handler instead of aborting
  the program with `SIGABRT`.
- Undefined behaviour when the solver was destroyed: the contact model base class had no virtual
  destructor.
- One damaged cell ended the whole run: an error thrown while refining one cell's mesh reached
  the error handler and stopped the simulation (in one 8-core paper-configuration run at 79,635
  cells). The cell is now removed instead.
- Six error checks never took effect: in the time integration (unsupported combinations of
  compile-time models) and in the automatic polarizer (an unknown region label), the error object
  was created but not thrown. These branches are not compiled in the default configuration.
- A parameter file that is not valid XML was reported as "could not be found ... must be an
  absolute path". A missing file, an unreadable file and an XML parse error (with its line) are now
  reported separately; relative paths are accepted, as they always were.
- `scripts/screening_analysis/utils/compute_IoU_euler.py` failed with `UnboundLocalError` when
  given explicit indexes.

## Performance

- One OpenMP thread is pinned to each physical core by default. `--threads=N` overrides the
  thread count, and `SIMUCELL3D_PIN_THREADS=0` turns pinning off. See
  {doc}`/user_guide/18_parallel_performance`.
- Adaptive OpenMP scheduling, selected with `--schedule` (default `adaptive`). *(2.0)*
- The spatial grid (USPG) stores voxels in vectors ordered along a Morton curve. *(2.0)*
- Optional sweep-and-prune contact detection, selected with
  `<contact_detection_algorithm>sweep_and_prune</contact_detection_algorithm>` in the parameter
  file; the USPG remains the default. *(2.0)*
- Face-face contact uses a compact face grid and splits the work of very large cells across
  threads. With 2,600 cells on 4 threads the contact step fell from 1,059 ms to 500 ms per
  iteration.
- In 8-core runs of the paper-configuration growth simulation, 2.1 needs 44-46% less time per
  iteration at 30,000 cells than the previous development builds, and reaches 30,000 cells in
  about 4 hours. Release 1.0 with only the local-id crash fix needed 28.5 hours. Because the
  physics also differs, this last comparison is not like-for-like.

## Engineering

- The project was renamed from DCM to SimuCell3D, and the source layout and build were
  reorganised. *(2.0)*
- Per-iteration diagnostics CSV (`performance_diagnostics.csv`, or the path given with
  `--diagnostics-csv=PATH`). *(2.0)*
- The test suite grew from 126 registered CTest targets in 1.0 to 340.
- Run launchers live in `scripts/runs/`; the long-run growth configuration is
  `parameters/longrun_fast_growth.xml` ({doc}`/examples/growth_from_one_cell`).
- `simucell3d --version` prints the version and the git commit the build was configured from.
- CMake 3.10 or newer is required, and CMake 4 is supported.
- Continuous integration builds and tests on GCC 10 (Debian 11) and GCC 13 (Ubuntu 24.04), with
  sanitizer builds and the Python bindings; the long test tier runs for releases and on request.
  Releases follow
  [`RELEASING.md`](https://github.com/nilesh-patil/simucell3d/blob/main/RELEASING.md), and this
  documentation is published at <https://nilesh-patil.github.io/simucell3d/>
  ({doc}`/developers/continuous_integration`, {doc}`/developers/release_process`).

## Known issues

- **Cells interpenetrate**, in every version including 1.0. A likely cause is that, in the paper
  configuration, the contact cutoff ($2\times10^{-7}$ m) is five times smaller than the minimum
  edge length ($10^{-6}$ m).
- **Some divisions are deferred, more often as the tissue grows.** In an 8-core run of the paper
  configuration from 1 to 150,498 cells, 14% of division attempts were refused: 5% below 30,000
  cells, rising to 21% between 125,000 and 150,000 cells. A refused mother was refused 1.75 times
  on average (median 1, at most 31). At a fixed shape some mothers are refused every time until
  the cell's shape changes.
- **Rare blow-ups of single nodes.** Occasionally a node is thrown far from its cell in one time
  step. The unstable-cell safeguard removes the cell and the run continues, but neighbouring cells
  can be removed with it. The cause is not yet known.
- **Unchecked lookups in `noexcept` functions.** A few edge and face lookups on the mesh
  refiner's path still end the program with `SIGABRT` if a mesh is damaged.
- **Stale coupling links.** When a node switches to a closer coupling partner, its old partner
  keeps a link back to it until the coupling maps are rebuilt. Present since 1.0.
- Contact models 0 and 1 still add contact forces without an atomic add. The default and paper
  configuration uses model 2, which is fixed.
- **Multi-threaded runs are not bit-reproducible.** Two runs with the same input and more than one
  thread can give slightly different results.
- **Unknown command-line options are ignored.** `simucell3d` silently ignores an option it does
  not recognise, for example a misspelt `--thread=4`.
- **The Python module has no tests of its own.** Continuous integration builds the Python
  bindings and imports the module, but does not run a simulation through it.
- **Bending force prefactor.** The bending force uses a prefactor of 3 where the Methods of the
  paper use 2, so the implemented force is 1.5 times the gradient of the bending energy written in
  the paper; the `bending_energy` written to the output uses the paper's formula. Unchanged since
  1.0. See {doc}`/user_guide/02_cell_mechanics`.

## Upgrading from 1.0

- The executable is still `build/simucell3d`, and a 1.0 command line
  (`./simucell3d <parameter file>`) is still accepted. Parameter files moved from the
  repository root (1.0) to `parameters/core/`, so 1.0 commands such as
  `./simucell3d ../parameters_default_dynamic.xml` need the new path
  (`../parameters/core/parameters_default_dynamic.xml`).
- The XML tags of 1.0 parameter files are still read. The optional tag
  `<contact_detection_algorithm>` is new in 2.0 ({doc}`/user_guide/11_parameter_file`).
- `OMP_NUM_THREADS` no longer sets the thread count; use `--threads=N`
  ({doc}`/user_guide/13_running_simulations`).
- Expect different trajectories (see the note at the top of this page), and check the standard
  error log and the `unstable_cells_removed` column for safeguard actions.
